Turning your recordings into tracker data

How your MapleStory Classic videos make the tracker better, what to export from Premiere, where to put the files, and what the script does with them. Written 2026-11-01.

First, what "training Claude" really means here

I don't learn from videos the way a person does. Nothing I watch changes me: my model never updates, and the next chat starts with no memory of this one. If you sent me a video today, a fresh session tomorrow would know nothing about it.

What does last is the repo. Every useful thing a video teaches us gets written down as code, tests or notes, and every future session reads those. So the right question is "how do we turn your recordings into things the tracker keeps?"

Doesn't carry over
  • Me "watching" footage
  • Anything said only in chat
  • A one-off answer about one clip
Carries over forever
  • Labeled frames saved as test fixtures
  • Regression tests CI runs on every push
  • Templates and calibration for other UI scales
  • Measured numbers with the clip as their source
  • Notes in docs/ai/

A good way to picture it: each labeled frame is a flashcard with the answer on the back. The tracker's readers take the whole stack as an exam on every push. When one of them gets a card wrong, we fix the reader and the card stays in the stack, so the mistake can't come back.

Everything below reads recorded pixels after the fact. No game memory, no packets, no input. Same rule as the tracker itself.

The pipeline

1 · MarkYou drop markers in Premiere on moments that matter
2 · DropVideo + markers CSV into the frames folder
3 · ReadScript samples frames, runs the tracker's own readers
4 · FixYou correct only the rows it got wrong
5 · KeepGood frames become fixtures and tests in the repo

Purple border = your part. Steps 3 and 5 are mine.

1 · What to record and how to mark it

The most important rule: give me the recording as close to raw as you can. Every re-encode blurs the UI a little more, and the readers depend on the UI's pixel grid (you play at 2560x1440 with UI "Ideal Ratio", so every UI pixel is a crisp 2x2 block). So the best workflow is not to export at all. Leave the original file alone, use Premiere only to place markers, and export just the markers list.

The MS Classic Markers panel built

Install once: double-click install.cmd in the panel folder, restart Premiere, then open Window › Extensions › MS Classic Markers. Click inside the panel and use the keys while you scrub:

KeyMarkerCovers
1misread5 s before to 5 s after the playhead
2 / 3 / 4loot / levelup / death-3/+5 s, -3/+3 s, -6/+2 s
5 to 8potion, map-change, party, chata few seconds around the playhead
9 / 0 / Mproc / kpq-stage / measureranges: press at the start, press again at the end
N, Z, Enote, undo, exportN types a note for the next marker

Export writes one CSV per recording, next to the recording, in that recording's own time. So you can trim, rearrange and put many recordings on one timeline, and the times still point at the right spot in each original file. The script finds that CSV by itself.

Not tried in a real Premiere yet: your first install is the test. If a button shows an error, send me a screenshot of the panel.

Marker names without the panel

Plain Premiere markers (press M) work too if you name them with these words. Give a marker a duration (drag its right edge) when the moment lasts a while, like a KPQ stage.

lootlevelupdeathpotionprockpq-stagemap-changepartymisreadskill-arrow-blowchat

misread is the most valuable one: any time you noticed the tracker show something wrong while you played, mark it. Without the panel, export the list with File › Export › Markers… as CSV, saved next to the video with the same name (run-05.mp4 + run-05.csv). Those times are sequence times, so this only lines up when the sequence is one untrimmed recording starting at 0. The panel's export doesn't have that limit.

If you do export from Premiere

Only when you want to trim a long recording into short clips. Start with right-click the clip › New Sequence From Clip so the sequence matches the recording exactly, then export with:

SettingValueWhy
Format / presetH.264, "Match Source – High bitrate"Keeps size and frame rate identical to the recording
Frame sizeSame as recording (2560x1440)Any resize smears the 2x UI grid. Never use "Scale to Frame Size"
Frame rateSame as recordingThe script samples 2 frames a second anyway, like the tracker
Time interpolationFrame SamplingFrame Blending or Optical Flow invent in-between frames
BitrateVBR 2-pass, target 40, max 50 Mbps my estimateEnough to keep small UI digits sharp. If a clip misreads, try higher before blaming the reader
EffectsNoneNo Lumetri, zoom, speed changes, text, webcam or transitions. Speed changes break every timing we measure

I tested the readers on an H.264 clip made from two of your real frames: the EXP bar read exactly the same as from the PNGs. That's a much cleaner encode than a real recording, so treat the bitrate above as a starting point, not a proven number.

3 · What the script does built

tracker/scripts/video2fixtures.js is in the repo now. One command per video:

node scripts/video2fixtures.js "…\videos\run-05.mp4" --markers "…\videos\run-05.csv"
  • Samples frames with ffmpeg at 2 per second, the tracker's own read rate, straight into memory. With a markers file it only reads each marked range plus 2 s on either side, so a 30-minute video with 10 markers takes seconds.
  • Auto-labels with the tracker's own readers. Every frame goes through the same code the app runs on a live capture: EXP bar, pickup lines, KPQ clock, party bars, Final Attack proc. The EXP bar checks itself, because EXP divided by the level's total has to match the %, so most frames are labeled with no help from you.
  • Saves only frames worth a look: the first one, one every 30 s, any frame where the EXP bar stops reading, goes backwards or jumps more than a level's worth, and any frame with a loot, KPQ or proc event. Capped at 150 per video.
  • Writes labels.csv (one row per saved frame: time, marker, what was read, why it was saved) and summary.json, which includes the EXP bar hit rate for the whole video. That rate is a score we can compare between tracker versions.

4 · Your part: fix the misses

Open labels.csv in Excel. For each row, glance at the PNG next to it. If the read is right, leave the row alone. If it's wrong, type the real value in fix_exp, fix_pct or fix_level, or describe it in notes. Most rows should need nothing.

5 · Keeping them next to build

A --promote step that takes your corrected CSV, crops each frame to the UI areas that matter (so the repo doesn't fill with 4 MB screenshots), saves it under tracker/tests/frames-video/ with its expected values, and adds it to the CI test. Every row you corrected becomes a test that fails until the reader is fixed.

Which tracker features gain the most

1

Loot and meso pickup lines. The hardest reader. Busy pickups stack and fade, and screenshots only catch one moment. Video shows the whole sequence, so we can check every line was counted once. Mark loot on your busiest fights.

2

EXP bar and EXP/hr. Labels itself, so every minute of footage is free test data. Long runs also give measured EXP/hr per map with the clip as the source, which the site's Where to train page can cite.

3

KPQ rounds. Full rounds test the clock reader on every stage and give real stage timings for the scoring references (scores stay provisional until 10 rounds per stage).

4

Buffs and timers. This already worked once: your 60 s Final Attack clip taught the proc reader all 10 countdown digits. Clips of other buff icons running down would do the same for them.

5

Other UI scales. If you record a few minutes at 1080p (UI 1.5x) or windowed, those clips calibrate the readers for players who don't run your setup. The site's screenshot import already needed this for a 1.875x tester.

6

Hitbox and skill measurements. Our notes have an open question on Arrow Blow: OSMS gives 470 px reach with ±137 px vertical, another reading gives 144 px up and 88 down. At native 1440 the game world isn't scaled, so one screen pixel is one game pixel. A clip of you firing at mobs on platforms at different heights, stepped frame by frame, can show which one the Classic client uses.

Good first batch

  • Three event clips with misread markers, from times you saw the tracker get something wrong
  • One 15-minute grind run on a single map, with loot markers on busy fights
  • One full KPQ round
  • One Arrow Blow measurement clip, if you want to settle the vertical-range question
